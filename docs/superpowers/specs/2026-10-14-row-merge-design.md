# 同人多条合并（合并发放）设计

日期：2026-10-14 · 状态：已与用户逐项确认（brainstorming 产出）

## 1. 背景与目标

同一批次的结算人员可能有多条记录——真实样例（2026-10-14 广州酒家餐饮服务人员 9 月账单，
71 条有效数据）中 3 人各 2 条：黄卫娣/王国芳分属两家门店（中华广场店 + 星樾城）各一条，
易文英同店跨 9 月/10 月两条。重复条目的姓名/身份证/卡号/手机号完全一致，差异在门店、
上班时间、工时与各金额列。

目标：作为**可选项**，把批内同人多条合并成一条发放记录——金额求和、要素一致、差异可
追溯。与「多列金额拆行」（2026-10-15-amount-split-rows-design.md，其非目标里明确搁置的
"跨行同名合并"即本功能）互为镜像，沿用同一模式：纯函数 + 确认映射时改行 + 预警条 dry-run，
导出面零改动。

### 已确认的关键决策（2026-10-14 与用户逐项确认）

1. **映射页全局开关**：默认关，localStorage `tc-merge-duplicate-rows` 记忆到本浏览器；
   统计条实时 dry-run 预览（与拆行备注开关同模式）。不采用导出预览手动选行合并。
2. **判重键：身份证优先 + 姓名+手机号兜底**：身份证列存在且行内有值 → `id:证号`；
   否则 `姓名|手机号`（同样归一）；两者都缺的行不参与自动合并并在预警条注明。
   同名不同证绝不合并。
3. **金额逐列求和**；组内**已映射要素列**（姓名/证号/手机/卡号/开户行等，金额与备注除外）
   归一后比对不一致 → 整组**不合并**、预警标红待人工；**未映射列取首条**，文本型差异
   拼接进备注。
4. **备注只拼文本型差异**：差异值剥去千分位/小数点/空白后仍含非数字字符的列才写
   （门店「中华广场店、星樾城」、上班时间「9月、10月」保留；序号 45/49、工时单价
   26.05/25.87 等纯数字噪声自动过滤）。格式 `原备注；列头：v1、v2`，多列差异以「；」相连；
   备注列不存在则跳过（不建虚拟列——与拆行不同，合并不需要保证源侧有备注）。
5. **单数据源内合并**：跨文件/sheet 不判重（与拆行、姓名清洗的按源处理口径一致）。
6. **方案 A：确认映射时合并**（`core/mapping/row-merge.ts` 纯函数）：执行顺序
   **姓名清洗 → 同人合并 → 多列拆行**——先归并同人原始条目（逐金额列求和），再交拆行
   按笔展开。导出预览/备注面板/KB 匹配/整理表直接导出看到的已是合并后行，下游零改动。

### 非目标（本期不做）

- 导出预览手动选行合并（触发方式已定为全局开关）
- 跨数据源判重合并
- 门店/工时等列的智能求和（工时单价这类不可加数值无法可靠区分，统一取首条）
- 判重键的模糊匹配（同 idCard 但姓名不同视为要素冲突标红，不自动合并）

## 2. 交互设计（映射页）

- 统计条新增开关行「同人多条合并」勾选框（默认不勾）。
- **开启且有重复**（蓝色信息条）：「同人合并：3 组重复（黄卫娣×2、王国芳×2、易文英×2），
  确认后 **71 → 68 行**」；有要素冲突组追加橙色明细：「黄卫娣 卡号不一致
  （6217…2827 / 6217…0827），该组不合并」；有键缺失行追加「N 行缺身份证且缺姓名/手机号，
  不参与合并」。
- **开启无重复**：「同人合并：未发现同人多条」。
- **未开启但检测到重复**（灰色提示条）：「检测到 N 人有多条记录（…），勾选『同人多条合并』
  可在确认时合并发放」——引导但不打扰。
- 确认映射时存在冲突组 → confirm 弹窗列出（沿用拆行核对不平弹窗模式：返回修改 / 仍要
  继续，冲突组保持不合并，数据不静默带病下发）。
- 开关切换/列标注变化 → 映射页重渲染，dry-run 实时跟随（onMapChange 重渲染机制已存在）。

## 3. 合并规则（纯函数，按数据源独立执行）

1. **判重键归一**：参与判重的值先去所有空白（含换行——样张卡号实测带 `\n` 尾巴）；
   身份证列存在且有值用 `id:证号`，否则姓名+手机号都有值用 `np:姓名|手机号`，否则无键。
2. **分组**：按判重键分组（保持首现顺序），单行组原样保留。
3. **要素一致性**：组内已映射要素列逐列比对（忽略空值、归一空白后比对）——出现 ≥2 个
   互异非空值 → 整组不合并，收集冲突明细（列号 + 各异值）。
4. **金额求和**：合并组的每个金额列独立求和；按最大小数位对齐（整数缩放）避免浮点累加
   误差；不可解析视同 0，全部不可解析则保留首条原值。
5. **要素列取值**：无冲突列取组内**首个非空原值**（防 OCR 半行空值卡位）。
6. **未映射列**：一律取首条原值；文本型差异列（≥2 互异值且非纯数字）去重后拼接进备注。
7. **合并行位置**：取组内首行位置；行宽对齐到组内最宽行。
8. **无键行**：原样保留并计数（`noKeyCount`）。

## 4. 技术设计

- **`src/core/mapping/row-merge.ts`（新增，纯函数）**：
  `mergeSamePersonRows(dataRows, opts)` → `{ rows, dupGroups, groups, conflicts, noKeyCount }`
  - `opts`: `{ typeToCol, amountCols, labelOf?, merge? }`（typeToCol 为 confirmMapping 口径，
    函数内部排除 amount/amountTotal/note 得到要素列集合）；
  - `merge: false`（产品默认关）或无重复组/无姓名无证号列 → **返回原数据引用**（字节级
    不变，compare 基线零变化硬门槛），同时仍报告 `dupGroups` 供关闭态提示；
  - `dupGroups` 为全部键重复组（含冲突不合并的），`groups` 仅实际合并的组。
- **`ui/steps/mapping.ts`**：
  - `MERGE_DUP_KEY = 'tc-merge-duplicate-rows'` + `mergeDupRowsOn()`（默认 false）；
  - `showMappingStep`：构建 typeToCol/amountCols（与 confirmMapping 同口径），先跑合并
    dry-run（merge 开关态都要跑以取 dupGroups），开启时把合并后行喂给拆行 dry-run，
    保证两预警条行数口径衔接；渲染开关 + 各状态提示；
  - `confirmMapping`：姓名清洗后、拆行前调用（`merge: mergeDupRowsOn()`）；
    conflicts 非空 → 汇总文案（每源一段，组名 + 冲突列值），confirm 弹窗；
  - `initMappingDelegates` 新增 `mergeToggle` change 分发（写 localStorage 后重渲染）。
- **导出面零改动**：导出预览/备注面板/KB 匹配/整理表直接导出看到的已是合并后行。

## 5. 边界与风险

| 项 | 处理 |
|---|---|
| 开关默认关 | `merge:false` 返回原引用，compare 208 产物零变化 |
| 卡号/证号/手机号带 `\n`、空格 | 判重与比对前统一去空白 |
| 同名不同证 / 同证不同名 | 键不同或要素冲突 → 不合并 |
| 组内某行卡号为空 | 空值不参与冲突判定，合并取首个非空值 |
| 金额列全空/不可解析 | 保留首条原值，空金额交给下游过滤逻辑 |
| 与拆行叠加 | 先合并（逐金额列求和）后拆行，行数口径两预警条衔接 |
| 图片源 | 合并前已完成清洗/校验；`dataRowsOverride` 人工编辑口径与拆行一致 |
| 备注列不存在 | 差异静默丢弃（目标模板无备注列同样忽略） |
| 整理表直接导出 | 与拆行同口径，看到合并后行；原表导出不受影响 |
| 合并后行数 | 统计条提前预告；导出预览已有增量机制 |

## 6. 测试与验收

- **单测（vitest）**：row-merge 规则矩阵——身份证判重与小数精度求和、空白归一（`\n` 尾巴）、
  姓名+手机兜底与同名不同手机不合并、同证异名冲突、冲突忽略空值、多金额列逐列求和与
  全空保留、未映射列首条 + 文本差异写备注 + 纯数字过滤、无备注列跳过、无键行保留计数、
  无重复返回原引用、`merge:false` 原引用但报告 dupGroups。
- **compare 红线**：208 产物零变化（开关默认关，compare 不经 UI）。
- **浏览器验收**：真实账单（本地调试，不入库）+ 合成 CSV 各一遍——核对 71→68、备注差异
  拼接、冲突标红与弹窗路径、开关记忆。
