# 2026-07-16

## 修复：灵工转换工具误把"平台服务费"等费用行导出为人员记录
- 问题：同事在费用明细底部追加"额外服务费/平台服务费"等汇总行时，工具会把它当成一条人员发放记录导出（移步到岗、身边云结果都出现）。
- 根因：`hasIdentityField()` 把"平台服务费"（5个汉字）误判为人员姓名（原逻辑：2-15个中文字即计 name 分，满足 `identityCount>=2` 即接受该行）。
- 修复（template-converter.html）：
  - 新增 `FEE_LABEL_RE`（费|平台|服务|合计|小计|金额|账号|银行…），该类标签不再被当作姓名。
  - `hasIdentityField` 改为**多重校验**：必须有强身份标识（身份证/统一社会信用代码/手机号/银行卡号其一）才算人员记录；兜底仅允许"拟似姓名(2-15汉字)+金额+≥3列"。
  - `smartDetectTable` 增加 `filteredCount`（被过滤的非人员行数），并在"列映射"步骤顶部显示"🛡️ 已自动过滤 N 行非人员记录"提示。
- 验证：Python 端口对杉垦/南沙云杉(个体户)/梧桐苑 三个真实文件逐行断言全部通过；Node 端口端到端跑杉垦费用明细 → 导出仅 2 名真实人员，平台服务费与合计行均被过滤。
- 注意：南沙云杉的"个体户/单位"收款人靠"统一社会信用代码(18位字母+数字)"识别为强身份，务必保留该规则，否则会误删单位行。
