# 灵工模板知识库自动填充 Spec

## Why
当前本公司模板输出17列中有6列（平台、商社编号、任务清单、税源地、工种、签约费率）依赖公司业务库数据才能填充，用户需手动逐行填写，效率极低且易出错。引入知识库机制可自动匹配补全这些字段。

## What Changes
- 新增"知识库管理"模块，支持上传/更新灵工商社数据等业务库文件
- 知识库数据采用 **localStorage + JSON文件导出/导入** 双重持久化策略，防止浏览器清缓存丢失
- 新增"商社编号"列识别类型，用于关联知识库
- 云杉模板生成时，自动根据商社编号匹配知识库，填充平台、税源地、任务清单、工种等字段
- 动态生成配置表和任务清单Sheet（不再依赖上传模板文件）
- 导出云杉模板时自动附带知识库JSON备份文件

## Impact
- Affected code: `template-converter.html`（唯一代码文件，HTML+CSS+JS单文件）
- 新增知识库数据结构、localStorage读写、JSON导入导出逻辑
- 修改列识别类型（新增商社编号）、修改云杉模板生成逻辑、修改导出逻辑

## ADDED Requirements

### Requirement: 知识库数据持久化
系统 SHALL 提供双重持久化策略保障知识库数据安全：
1. 主存储：浏览器 localStorage，键名 `lg_knowledge_base`
2. 备份机制：每次导出云杉模板时，自动附带一个 `知识库备份_日期.json` 文件
3. 恢复机制：支持从 JSON 文件重新导入知识库数据

#### Scenario: 浏览器清缓存后恢复
- **WHEN** 用户浏览器清除了缓存导致 localStorage 丢失
- **THEN** 用户可通过之前导出的 JSON 备份文件重新导入知识库，一键恢复全部数据

#### Scenario: 首次使用上传知识库
- **WHEN** 用户上传灵工商社数据 Excel 文件到知识库
- **THEN** 系统解析文件并存入 localStorage，同时显示已入库的商社数量和任务数量

### Requirement: 知识库管理界面
系统 SHALL 在工具顶部提供知识库管理区域：
1. 显示当前知识库状态（商社数量、任务数量、最后更新时间）
2. 提供"上传知识库"按钮，支持上传 Excel 文件
3. 提供"导出备份"按钮，将知识库导出为 JSON 文件
4. 提供"导入备份"按钮，从 JSON 文件恢复知识库
5. 提供"清空知识库"按钮（需二次确认）
6. 上传新知识库时，与已有数据按商社编号合并（新数据覆盖旧数据）

#### Scenario: 上传知识库文件
- **WHEN** 用户点击"上传知识库"并选择 Excel 文件
- **THEN** 系统解析文件，提取商社编号、商社简称、商社全称、签约费率、签约主体、任务名称、服务内容等字段
- **AND** 显示"已入库 XXX 个商社，XXX 条任务"

#### Scenario: 导出知识库备份
- **WHEN** 用户点击"导出备份"
- **THEN** 系统将 localStorage 中的知识库数据导出为 JSON 文件下载

### Requirement: 商社编号列识别
系统 SHALL 在列映射步骤中新增"商社编号"识别类型：
1. 在 COL_KEYWORDS 中新增 `shangSheId: /商社编号|商社代码|商户编号/`
2. 在 COL_TYPE_LABELS 中新增 `shangSheId: '🏢 商社编号'`
3. 自动识别源数据中的商社编号列

#### Scenario: 自动识别商社编号列
- **WHEN** 源数据表头包含"商社编号"关键词
- **THEN** 系统自动将该列映射为"商社编号"类型

### Requirement: 云杉模板自动填充
系统 SHALL 在生成云杉模板时，根据知识库数据自动填充以下字段：

| 输出列 | 填充逻辑 |
|--------|----------|
| 平台 | 根据商社的"签约主体"匹配配置表中的平台选项 |
| 商社编号 | 从源数据的商社编号列直接取值 |
| 任务清单 | 根据商社编号匹配知识库中的任务，生成"序号.任务名(商社编号)"格式 |
| 税源地 | 根据平台关联配置表中的税源地 |
| 工种 | 从任务清单中提取工种名称（序号.后面的部分） |

#### Scenario: 商社编号匹配成功
- **WHEN** 源数据某行的商社编号在知识库中存在
- **THEN** 自动填充该行的平台、税源地、任务清单、工种字段

#### Scenario: 商社编号匹配失败
- **WHEN** 源数据某行的商社编号在知识库中不存在
- **THEN** 该行相关字段留空，在预览中用橙色高亮提示"未匹配"

#### Scenario: 无知识库时生成模板
- **WHEN** 用户未上传知识库但选择了云杉模板
- **THEN** 系统正常生成模板，仅填充可识别的字段，空白字段不报错

### Requirement: 动态生成配置表和任务清单
系统 SHALL 在导出云杉模板时，根据知识库数据动态生成配置表和任务清单Sheet：
1. 配置表：从知识库中提取所有唯一的税源地和平台，按原模板格式排列
2. 任务清单：从知识库中提取所有商社的任务，按"序号.任务名(商社编号)"格式排列
3. 不再依赖上传模板文件来保留配置表

#### Scenario: 有知识库时导出
- **WHEN** 用户导出云杉模板且知识库有数据
- **THEN** 配置表和任务清单Sheet根据知识库数据动态生成

#### Scenario: 无知识库时导出
- **WHEN** 用户导出云杉模板但知识库为空
- **THEN** 配置表和任务清单Sheet使用默认空模板结构

### Requirement: 导出时自动附带知识库备份
系统 SHALL 在导出云杉模板 Excel 时，同时自动生成并下载一个知识库 JSON 备份文件：
1. 文件名格式：`知识库备份_YYYYMMDD.json`
2. 仅在知识库非空时生成
3. 用户可保存此文件用于未来恢复

#### Scenario: 导出云杉模板时有知识库
- **WHEN** 用户导出云杉模板且知识库有数据
- **THEN** 同时下载 Excel 文件和 JSON 备份文件

### Requirement: 签约主体与平台的映射规则
系统 SHALL 维护签约主体到平台的映射关系：
- "佛山云杉人力资源服务有限公司" → 匹配配置表中包含"佛山"或"甲乙"的平台
- "广州云杉人力资源服务有限公司" → 匹配配置表中包含"广州"或"云杉"的平台
- "广州南沙云杉人才服务有限公司" → 匹配配置表中包含"南沙"的平台
- "广州国联咨询服务有限公司" → 匹配配置表中包含"国联"的平台
- 其他签约主体 → 尝试模糊匹配，匹配失败则留空

#### Scenario: 签约主体匹配成功
- **WHEN** 商社的签约主体为"佛山云杉人力资源服务有限公司"
- **THEN** 平台字段自动填充为对应的平台编号和名称

## MODIFIED Requirements

### Requirement: 云杉模板导出逻辑
原逻辑依赖上传模板文件保留配置表和任务清单，现改为从知识库动态生成。无知识库时回退到空模板结构。

### Requirement: 列识别类型
在原有9种识别类型基础上新增"商社编号"类型。
